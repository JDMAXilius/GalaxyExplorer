# UI 2.0 in Unity — approach and roadmap

Written 13 Oct 2026 by the terminal session. Status: **proposal, nothing implemented**. It is based on a read of the code on `quest3-port` (code wins over docs) and on Unity and Meta documentation checked the same day. Nothing here has been tried in the editor or on a headset.

The design being implemented is the Figma file `dx6MxAxPqZ9QBSRJqCCVev`, `V2 /` pages, with node IDs in `FIGMA_PROGRESS.md`.

## 1. What the code looks like today

- **One shipping tree, one parked tree.** `Assets/scripts/` with `main_scene` + `core_systems_scene` is the product (owner's call, 13 Sep 2026). `Assets/Cosmic/` is a complete rebuild that is parked and disabled in the build.
- **UI is generated by code.** `UiPrefabBuilder`, `DesktopDockBuilder`, `GalaxyBarBuilder` write prefabs into `Assets/prefabs/ui/`. Headset UI is world-space uGUI at 1 mm per unit with TextMeshPro (Selawik).
- **Two input paths.** World UI is hit by physics: every control is a `BoxCollider` + `GEInteractable` + poke filter + handler (`GEButton`). Desktop UI is separate screen-space canvases with uGUI `Button`s. There is no generic toggle, list or menu.
- **Navigation lives in the dock.** `ExperienceDirector.Switch` changes place, but layout switching, tile lists and several helpers are static members of `DockController`, and the palm menu, the app check and Reset/About all reach through it.
- **No selection model.** "Which planet is selected" is inferred from `ForceSolver` states.
- **Data does not match the card.** `BodyInfo` has no image and four or five stats; 11 of 18 places have no thumbnail; there are no per-body photos.
- **Destinations are full places.** A nebula opens through `Switch`; there is no "back to map".
- **Narration starts by itself** in three places and `VOManager` has no pause.
- **The companion has four phases** (Idle, Listening, Thinking, Speaking), no Connecting or Unavailable state, no phase event, and no panel.
- **No compare feature, no lesson framework.** First-run hints are never triggered (`HintCards.ShowIfFirstRun` has no caller).
- **Verification is thin.** No test assemblies. `AppCheck` walks the dock by screen position. The backlog says the editor cannot enter play mode (CS-300).
- **The working tree is dirty.** About 30,000 lines of uncommitted scene changes plus the Steam S1 edits touch `DockController`, `DesktopDock`, `EnvironmentController` and others.

## 2. Decisions and why

### 2.1 Build on the shipping tree, in a new folder

New UI goes in `Assets/scripts/ui2/` with its own assembly definition, and talks to the app only through a small set of adapters (section 2.4). Legacy UI scripts are not edited to fit; they are switched off surface by surface and deleted at the end.

The parked `Assets/Cosmic` tree is not revived. Its UI layer is useful as reference only (theme asset, panel host, prefs wrapper).

### 2.2 Keep uGUI + TextMeshPro, world space

UI Toolkit world-space panels are not ready for this app. XR Interaction Toolkit 3.2 shipped them as pre-release with poke and near-far only, no ray interactor, and scroll limitations; the project is on XRI 3.6 and whether ray support has since landed is unverified. The app needs ray, poke, controller and mouse on day one, so uGUI stays.

### 2.3 One input path: every control is a press target

The V2 design has no slider and no scrolling list. Toggles, segmented choices, menu items, list rows, tiles, pins and chips are all "press this". So the existing physics path is enough:

- One new `UiButton` component: collider sized automatically from its `RectTransform`, with Default / Hover / Pressed / Selected / Disabled / Focused visuals driven by the theme. It sits on the existing `GEInteractable` events, so hand ray, poke, controller and mouse all work unchanged.
- `UiToggle`, `UiSegment`, `UiMenu`, `UiListRow` are thin wrappers over `UiButton`.

**Desktop uses the same prefabs.** Instead of a second set of screen-space canvases, the desktop rig parents the same world-space shell to the camera and a `ScreenAnchor` component pins rail, dock, card and settings to the frustum edges. The mouse already raycasts physics. This removes the second UI implementation entirely and is the single biggest simplification available.

### 2.4 A model the UI can read, and adapters to the legacy app

A plain C# `AppModel` is the single source of truth for the UI, with change events:

| State | Values | Backed by |
|---|---|---|
| Context | Cosmic Web, Galaxies, Milky Way, Solar System | new `ExploreCatalog` asset mapping contexts to places |
| Place | current place, switching, failed | `ExperienceDirector.Switch`, `ExperienceChanged` |
| Selection | none, body, moon, destination | new `SelectionTracker` over `ForceSolver` states and picker presses |
| View (Solar) | Orbits, Equal Size, Relative Size | Orbits = place `solar_system`; the other two = `LayoutRig.Apply` on `solar_system_planets` |
| Room | on, off, unavailable | `EnvironmentController` |
| Narration | off, playing, paused | `VOManager` plus new pause/resume |
| Guide | idle, connecting, listening, thinking, speaking, unavailable, permission needed, mic unavailable | new `GuideStatus` derived from `Being.Phase`, `Being.Online`, `Mic.Permitted` |
| Panel | none, card, preview, guide, settings, help, confirmation | new `PanelHost`; one focused panel at a time |

Adapters are the only code that touches legacy classes. That is what lets the old dock be deleted without the new UI noticing.

### 2.5 Mechanics that have to change (not just visuals)

1. **Navigation.** Four contexts replace eleven dock tiles. Needs the `ExploreCatalog`, a breadcrumb, and "Back to map" (remember the Milky Way selection, `Switch` back to it).
2. **Selection.** A real selection service with events. Pressing a picker tile selects and pulls the body; pulling by hand updates the selection.
3. **Card data.** Add a photo and a "two headline facts" choice to `BodyInfo` and `ExperienceModule`; extend `docs/copy/*.md` and `CopyImporter`. Produce images for 17 bodies, 27 moons, 11 places and 7 nebulae (render from the scenes with the existing `ThumbnailBuilder` where possible).
4. **Narration on demand.** Listen starts it; remove or gate the three automatic starts; add pause and resume.
5. **Companion status.** Add Connecting and Unavailable, a phase event, and surface microphone permission and device errors.
6. **Layout plumbing.** Move layout requests and shared helpers off `DockController` statics.
7. **Settings.** Same PlayerPrefs keys. The content-scale slider goes. "Bring menu here" (`Recenter`) and "Restore scene" (`ResetPlaces`) become separate actions.
8. **Lessons.** Replace `HintCards` with a small lesson flow that actually runs on first use and can be replayed from Help.
9. **Palm summon.** Reuse the palm detection in `HandMenu` to bring the shell to the player; the old hand-menu prefabs go. Owner note on record: the palm menu is to be kept, so this is a restyle of what the gesture shows, not its removal.
10. **Compare.** A new feature. Planets first; hidden or disabled with a reason elsewhere.
11. **App check.** Rewrite `AppCheck` to drive the new shell by control id, not screen position.

### 2.6 Sizes and distances need a headset before they are fixed

Meta's hand-tracking guidance puts direct-touch panels at 42–46 cm with targets of about 22 mm, ray-cast UI at 0.8–3 m, and says to avoid the 0.5–0.8 m band. Targets should subtend roughly 2.5–3° either way, with 12 mm between them. The current dock parks at 0.8 m, on the edge of the band to avoid.

So Phase 0 includes a grey-box test on the Quest to choose between a near shell (rail and dock at touch distance, card by the object) and a far shell (everything at ray distance). The V2 millimetre proposals (80 mm rail, 24 mm targets, 170–200 mm card) are consistent with the near option but are unvalidated.

Meta reserves palm-up pinch for the system menu. The V2 palm summon is palm-toward-face without a pinch, as today, but it must be checked on device for clashes.

## 3. Roadmap

Each phase lands behind a `Ui2` switch so the old UI keeps working until cutover. Code tickets are [CC]; editor, build and device tickets are [TERM]. Every phase ends with a desktop run and a Quest run.

| Phase | Goal | Main work | Done when |
|---|---|---|---|
| **0 Ground** | Make the project safe to change | Fix play mode (CS-300). Land or park the dirty tree (CS-301, CS-317). Grey-box distance test on Quest. Export tokens to a theme asset and icons to sprites. Record the decisions in section 4. | Editor plays; tree clean; near-or-far decided with photos from the headset |
| **1 Foundations** | The kit everything else uses | `ui2` assembly, theme, `UiButton` and wrappers, `ScreenAnchor`, prefab builder, `AppModel`, adapters, new app check skeleton | A test panel with every control state works with poke, ray, controller and mouse |
| **2 Shell** | Get around with the new UI | Rail, dock (Explore, Guide, Room), settings button, room toggle, `ExploreCatalog`, breadcrumb. Old dock hidden when `Ui2` is on | Every place the old dock reached is reachable, on Quest and desktop |
| **3 Card and picker** | One card for everything | Selection service, top picker, `Card/Information`, photo and fact data, Listen with pause. Retire `InfoPanel` and `PlanetInfoCard` | Galaxies and planets show the new card; no old card appears anywhere |
| **4 Milky Way** | Map, preview, travel | Map pins, preview card, Enter, loading and failure notices, Back to map | Round trip to a nebula and back keeps the selection |
| **5 Solar System** | Views without the clutter | View chip and menu, body picker, moons, other star systems | Orbits, Equal Size, Relative Size and HD 110067 all reachable from the chip |
| **6 Settings** | Replace the utility window | Settings panel, device chooser, About, Quit and Restore confirmations. Retire `UtilityWindow`, `AboutSlate` | All existing settings work from the new panel |
| **7 Guide** | Give the companion a face | `GuideStatus`, Guide panel with all phases, permission and device errors, suggested questions | Ask a question end to end; failure and no-mic paths recover |
| **8 Help and first use** | Teach the gestures | Lesson flow, placement step, Help index, palm summon, tracking-lost notice | A new player is taught palm, pinch and two hands once, and can replay them |
| **9 Compare** | New feature | Choose second object, pair layout, compare card | Two planets compare at equal and relative size |
| **10 Cutover** | Remove the old UI | Delete legacy UI scripts, prefabs, builders and hand menus. Update GDD §8, `docs/ui/spec.md`, technical overview, credits. Performance pass. Full Quest walkthrough | No legacy UI code in the build; walkthrough clean |

Order of value if time is short: 0, 1, 2, 3 give a recognisably new app. 4 to 8 complete it. 9 can ship later.

## 4. Decisions needed from the owner

1. **Near or far shell** (after the Phase 0 headset test).
2. **Narration:** should it still start by itself when you pull a planet, or only from Listen?
3. **Card facts:** which two facts per kind of object (planet, moon, galaxy, nebula, place).
4. **Images:** render our own thumbnails from the scenes, or source credited observatory photos.
5. **Compare for galaxies:** by diameter, by distance, or not offered.
6. **Palm gesture:** keep it as the way to summon the menu.
7. **The parked `Assets/Cosmic` tree:** leave parked, or delete at cutover.

## 5. Risks

- **Dirty tree and blocked play mode.** Starting UI work before Phase 0 is done means merge pain in the same files and no way to verify.
- **Image production** is the largest non-code job (about 60 images) and gates Phase 3.
- **Distance and legibility** are unknown until tried on the headset; flat Figma pixels do not transfer.
- **Scope of Compare.** It is a feature, not a restyle; keeping it last protects the rest.
- **Two sessions, one editor.** Code and editor work must keep the ticket hand-off in `BACKLOG.md`.
